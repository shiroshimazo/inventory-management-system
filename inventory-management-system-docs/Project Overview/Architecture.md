## Overview

The Inventory Management System is currently a **frontend-only single-page application (SPA)**. It is built with React and TypeScript, bundled by Vite, and routed with TanStack Router. There is no backend or database in the codebase yet: all data shown in the UI is static mock data defined next to the pages. A backend (for example Supabase/PostgreSQL) is planned and can be added without restructuring the frontend.

## Layers

| Layer | Technology | Responsibility |
|---|---|---|
| UI components | React 19 + shadcn/ui (Base UI) + Tailwind CSS 4 | Render the interface |
| Routing | TanStack Router (file-based) | URL to page mapping, layouts, redirects |
| Data fetching | TanStack Query | Server state (configured, not yet used) |
| Tables | TanStack Table | Table state, sorting, filtering, pinned columns |
| Forms | React Hook Form + Zod | Form state and validation |
| Charts | Recharts | Dashboard visualizations |
| Animation | Motion | Sidebar and micro-interactions |
| Theming | next-themes | Light/dark/system theme |

## Routing and Layouts

- **`__root.tsx`** — wraps every route in `Providers` (theme, tooltip, sidebar) and renders the `Toaster` and `ScrollToTop`.
- **`_pages.tsx`** — the admin shell: collapsible `Sidebar`, sticky `Header` (breadcrumbs, mode toggle, language dropdown, profile dropdown), and `Footer`.
- **`_auth.tsx`** — a blank layout used by the authentication screens.
- **`index.tsx`** — redirects `/` to `/dashboard`.
- **`$.tsx`** — catch-all route. Every URL that does not match a real route renders the 404 page.
- **`routeTree.gen.ts`** — generated by the TanStack Router Vite plugin before TypeScript runs. Do not edit it by hand.

### 404 Handling

The 404 page is registered once, on the router in `src/router.tsx`:

- `defaultNotFoundComponent` — the `NotFound` component used for every URL that does not match.
- `notFoundMode: 'root'` — the 404 renders in the root layout, outside the admin shell. In the default `'fuzzy'` mode it renders inside the page the URL half-matched, which keeps the sidebar and a breadcrumb trail for a page that does not exist.

Both are needed: a URL such as `/dashboard/orders` half-matches the `/dashboard` route, so it reaches the router as "not found" on that route. A URL such as `/anything/else` matches the `$.tsx` catch-all route directly.

## Data Flow

**Current:** mock data arrays live in route files and views, then flow directly into presentational components. There are no API calls.

**Planned:** backend/API or Supabase → TanStack Query hooks → pages. The `QueryClient` is already configured in `src/router.tsx` (`staleTime` 5 minutes, `retry` 1), so data fetching can be plugged in later.

## State Management

- **Server state:** TanStack Query `QueryClient` (currently unused).
- **Local UI state:** React `useState`/`useReducer` inside components.
- **Theme state:** next-themes with the `class` strategy, defaulting to the system theme.
- **Sidebar state:** persisted in a `sidebar_state` cookie for one week.

## Build and Tooling

| Command                       | Action                                 |
| ----------------------------- | -------------------------------------- |
| `npm run dev`                       | Start the Vite dev server on port 3000 |
| `npm run build`                     | `vite build` plus TypeScript checks    |
| `npm run lint` / `npm run lint:fix` | ESLint checks                          |
| `npm run format`                    | Prettier formatting                    |
| `npm run check-types`               | TypeScript type checking               |

- Path alias: `@/*` maps to `src/*`.
- Production hosting must serve `index.html` for unknown application paths so direct links and refreshes work (SPA fallback).
